# 前端视觉设计与评审

> **加载场景**：做/改/评审页面、落地页、产品页、后台、仪表盘、表单、空态/错误态；需要视觉方向、设计系统、排版/色彩/布局/动效；页面“看起来像 AI 模板”；需要设计评审/浏览器验收时。
>
> **不适用**：纯后端、纯数据、无 UI 的任务。

## 一、先定方向，不先写代码

1. 读 brief：subject、audience、primary job、约束、真实内容/资产、现有 `DESIGN.md`/设计系统。
2. 判断 surface 模式：**Persuade / Operate / Read / Experience**；同一页面可有主模式，但不要后台套营销 hero。
3. 写 5–8 行视觉方向：关键词、排版、色彩、布局、图像、动效；说明“为什么适合这个 subject”。按 `frontend-design/brief-and-direction.md` 的 brief/方向结构填写；版式选型参考 `frontend-design/patterns.md`。
4. 需要参考图时收集 2–3 个，提取原则，不复制代码/文案/图片/标志性效果。

缺 subject/audience/job 时先问或明确假设；不要直接生成通用模板。

## 二、视觉质量底线

- **排版**：1–2 个字体家族；明确 type scale；正文行宽 65–75ch；标题不溢出；不要系统字体当 display，不要标题单词换色/全大写小标签/无意义 eyebrow/编号。
- **色彩**：先中性色再强调色；正文对比度 ≥4.5:1，大字 ≥3:1；彩色表面次级文字从色相/前景推导；暗色模式单独验证；不要默认紫/淡紫渐变。
- **布局**：一个屏幕一个主任务；左右边缘对齐；组内紧、组间松；卡片不是默认容器，禁止嵌套卡片；营销页首屏只放 hero。
- **材质**：边框/阴影/圆角统一 token；阴影有偏移+柔化；不要零偏移彩色光晕、硬偏移阴影、玻璃拟态当默认。
- **动效**：一个 orchestrated moment，不是每段 fade-up；只动 transform/opacity；尊重 `prefers-reduced-motion`；不做滚动劫持/随机闪烁。
- **图标**：统一线性/填充、粗细、圆角；不用 emoji/Unicode 字符当图标；不用画得像真 logo 的仿制品。
- **内容**：真实产品/场景/文案；没有就明确占位；不编客户 logo/评价/统计；不交付 lorem ipsum。

## 三、四态与可访问性

每个数据区域/页面必须有：

- loading：骨架/进度/文案，不是空白闪烁
- empty：为什么空 + 下一步
- error：发生了什么 + 恢复动作，不泄露内部细节
- 边界：超长文本、空数组、大量数据、权限不足、网络慢/断网

可访问性：

- 语义标签、表单 label、图片 alt、按钮可键盘触发
- focus ring 可见，不要全局 `outline: none`
- 触控目标 ≥44×44px；对比度达标；错误不只靠颜色
- modal/drawer 有 focus trap，关闭后焦点回到触发元素
- 动画有 reduced-motion 降级

## 四、反 AI 味

默认避免：

- 紫/淡紫渐变主视觉；三张同尺寸“图标+标题+文字”卡片；大数字+小标签 hero
- 每段 eyebrow、无意义 01/02/03、每段 fade-up、每卡 hover 同一效果
- 渐变文字、玻璃拟态、单边色条、硬偏移阴影、幽灵卡片、过度圆角
- emoji 当图标、系统字体当 display、假 logo/评价/统计、参考站资产
- `transition: all`、布局属性动画、滚动劫持

每条都要能被 brief 证明；否则替换，而不是“稍微调一下”。详见 `frontend-design/anti-slop.md`。

## 五、实现规则

- 先复用项目已有设计系统/组件/token；没有才新建。
- 不未经确认安装 UI 库/字体/图标包；先说明体积、许可、维护成本。
- 组件状态完整：hover/focus/active/disabled/loading/error/empty；不要只做成功态。
- 响应式至少覆盖 1440/1024/768/390；无横向滚动/溢出；移动端主任务优先。
- 浏览器默认表面（选择、caret、滚动条、focus ring、下划线、表格数字）与设计协调。
- 页面结构/组件/状态可维护；不要为一次性效果堆不可复用代码。

## 六、浏览器验收（必须）

在真实浏览器看渲染结果，不只看源码：

- 四个视口截图：1440×900、1024×768、768×1024、390×844
- 控制台无 error；无 404/CORS；无框架 warning
- 键盘走主流程；focus 可见；modal 可 Esc
- 四态实际可见；对比度抽查；reduced-motion 生效
- 图片/字体/异步加载完成后再截图；UI 改动有改前/改后
- 记录“已检查/未检查/无法验证”，不把“看起来不错”写成全部通过

详见 `frontend-design/browser-check.md`。

## 七、设计评审

按 `frontend-design/visual-review.md`：

- 先 brief 覆盖/第一眼/层级，再排版/色彩/布局/动效/状态/可访问性/响应式/内容诚实/独特性
- 认知负荷 8 项 + Nielsen 10 启发式（0–4）
- 发现分 P0–P3，写清位置/观察/影响/修复/验证
- 先修 P0/P1；每轮重截四视口；修改 token 同步 `DESIGN.md`

## 八、自检

- [ ] brief/模式/视觉方向明确，不是直接套模板。
- [ ] 排版/色彩/布局/动效有体系，无默认 AI 套路。
- [ ] 四态、键盘、对比度、reduced-motion 覆盖。
- [ ] 四视口真实浏览器验收，有截图/记录。
- [ ] 无假数据/假 logo/未授权资产；占位有标注。
- [ ] 没有未经确认新增依赖；token/组件复用合理。
- [ ] 设计评审发现已分级并处理/记录。
