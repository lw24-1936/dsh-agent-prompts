# 页面模式与版式

> 以下是“选择结构”的参考，不是模板。每个页面先有 brief，再选模式。

## 1. 落地页 / 产品页（Persuade）

结构候选：

1. **Hero**：一句主张 + 一个主 CTA + 真实产品/场景视觉；首屏不出现第二段标题。
2. **问题/现状**：用真实用户语言说明痛点，不用抽象大词。
3. **产品如何解决**：截图/演示/短流程，优先真实 UI。
4. **证据**：真实客户/案例/数据；没有就不编。
5. **细节/能力**：按用户任务组织，不按功能清单堆砌。
6. **异议处理**：价格/安全/迁移/集成等真实问题。
7. **CTA**：与首屏同一动作；不要多个互相竞争的主按钮。

避免：三卡片、紫渐变、大数字 hero、每段 fade-up、假 logo 墙。

## 2. 后台 / 仪表盘（Operate）

结构候选：

- 顶部：页面标题 + 全局筛选/时间范围 + 主操作。
- 左侧/顶部导航：≤5 个一级；当前位置可见。
- 主区：概览（关键指标/趋势）→ 明细表/列表 → 详情抽屉/页面。
- 表格：排序/筛选/分页/批量操作；空态与错误态；列宽可读。
- 设置/表单：分组、默认值、保存反馈、危险操作二次确认。

原则：熟悉模式优先；密度可高但层级清楚；不要营销页 hero；不要把所有指标都做成卡片。

## 3. 文档 / 内容（Read）

- 正文限宽 65–75ch；侧栏目录（层级 ≤4）；标题锚点。
- 代码块/表格/提示块有统一风格；可复制；长代码可折叠。
- 搜索/上一页/下一页；面包屑；最后更新时间。
- 排版优先，装饰克制；不要让导航抢正文。

## 4. 表单

- 标签在输入上方；必填/可选明确；placeholder 只做示例。
- 分组按用户任务；一屏不要太多决策；复杂表单分步/渐进披露。
- 错误就近、说明原因与修复；提交中禁用+反馈；成功有明确下一步。
- 危险操作：明确后果、二次确认/输入确认、可撤销优先。
- 键盘/自动填充/移动端输入类型正确。

## 5. 空态 / 错误 / 加载

- **加载**：骨架/进度/短文案；不要空白闪烁；长任务可取消。
- **空态**：为什么空 + 下一步（创建/导入/清除筛选）；不要只写“暂无数据”。
- **错误**：发生了什么 + 影响 + 恢复（重试/返回/联系）；不泄露内部细节。
- **权限不足**：说明需要什么权限/如何申请，不要假装 404。
- **边界**：超长文本、空数组、单条、大量、网络慢/断网。

## 6. 移动端

- 主任务优先；导航收敛；触控目标 ≥44px。
- 表格改卡片/横向滚动要有明确提示；不要挤压到不可读。
- 固定底部操作栏不遮挡内容；安全区适配。
- 图片/字体不造成布局抖动。

## 7. 设计系统 / DESIGN.md

至少记录：

- 颜色 token（背景/表面/文字/边框/主色/语义色/暗色）
- 字体与 type scale
- 间距/圆角/阴影/边框
- 组件状态与交互契约
- 动效时长/缓动/reduced-motion
- 图标风格/尺寸
- 页面模式与例外

新增页面优先复用 token/组件；一次性覆盖要说明原因，不要散落魔法值。

## 8. 产品基础清单（交付前）

- [ ] 404 页面：说明发生了什么 + 回首页/搜索，不只是框架默认页。
- [ ] favicon / app icon / 社交分享图（og:image，1200×630 左右）。
- [ ] 隐私政策/服务条款（按业务需要；草稿需用户确认，不冒充法律意见）。
- [ ] `DESIGN.md` / tokens 与实际样式一致。
- [ ] `prefers-reduced-motion` 有真实降级。
- [ ] README 有安装/运行命令，且命令真实存在。
- [ ] CI 跑测试；依赖扫描（Dependabot/Renovate）按项目启用。
- [ ] 错误监控/日志（按项目需要；DSN 走环境变量）。
- [ ] 迁移有回滚/向前兼容方案。
- [ ] 没有提交密钥/真实凭证。
