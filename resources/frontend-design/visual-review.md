# 视觉设计评审

## 1. 评审顺序

1. **Brief 覆盖**：subject/audience/job/内容是否完整？主 CTA 是否唯一？
2. **第一眼**：3 秒内知道这是什么、对谁、下一步做什么？
3. **层级**：主视觉/主标题/正文/次要动作是否一眼可分？
4. **排版**：字体/字号/行宽/行高/字重/换行；是否有溢出/孤字/过窄行宽。
5. **色彩**：对比度、语义色、暗色模式、彩色表面上的次级文字。
6. **布局**：栅格、边距、对齐、组内/组间节奏、卡片滥用、嵌套卡片。
7. **动效**：是否只有一个主时刻；是否尊重 reduced-motion；是否干扰操作。
8. **状态**：hover/focus/active/disabled/loading/empty/error/边界。
9. **可访问性**：键盘、focus 可见、语义标签、表单 label、图片 alt、对比度。
10. **响应式**：1440/1024/768/390；无横向滚动/溢出/触控目标过小。
11. **内容诚实**：真实数据/占位标注；无假客户/评价/统计/logo。
12. **独特性**：是否像这个 subject 的设计，而不是通用模板。

## 2. 严重度

| 级别 | 含义 | 例子 |
|---|---|---|
| **P0** | 阻断交付 | 主流程不可用、移动端溢出、对比度不可读、键盘不可达、假数据/假 logo、未授权品牌资产 |
| **P1** | 明显缺陷 | 层级混乱、核心 CTA 不突出、四态缺失、字体/间距不成体系、动效干扰 |
| **P2** | 需要改进 | 版式节奏、细节对齐、色彩微调、文案不一致 |
| **P3** | 可选润色 | 微交互、纹理、装饰细节 |

评审输出：

```md
- [P0/P1/P2/P3] 问题（文件/路由/选择器）
  - 观察：
  - 影响：
  - 修复：
  - 验证：
```

不要只说“感觉不对”；必须指出具体元素、影响和可验证的修复。

## 3. 认知负荷（8 项）

- [ ] 单一焦点：主任务不被竞争元素打断
- [ ] 分组：信息按 ≤4 项一组
- [ ] 接近性：相关内容视觉成组
- [ ] 层级：一眼看出最重要内容
- [ ] 一次一件事：不要求同时处理多个决定
- [ ] 选项数量：决策点 ≤4 个可见选项
- [ ] 工作记忆：不需要记住上一屏信息才能操作
- [ ] 渐进披露：复杂内容按需展开

2–3 项失败 = 中等，尽快修；4+ = 高，必须修。

## 4. Nielsen 10 启发式（0–4 分）

1. 系统状态可见（loading/成功/失败/进度）
2. 系统与真实世界匹配（用户语言，不堆术语）
3. 用户控制与自由（撤销/返回/取消）
4. 一致性与标准（同一动作同一表现）
5. 错误预防（约束/确认/默认值）
6. 识别而非回忆（选项可见，不靠记忆）
7. 灵活高效（快捷路径/默认值/批量）
8. 美观与极简（每屏只放必要信息）
9. 帮助识别/诊断/恢复错误（说清问题与下一步）
10. 帮助与文档（就近、可搜索、不过度）

评分不是目的；找出最低分的 2–3 项并给修复。

## 5. 视觉质量检查

- 标题/正文比例是否明确？是否有 3 个以上同权重元素？
- 行宽是否 65–75ch？长文是否可读？标题是否溢出？
- 颜色是否全部来自 token？有无未定义的“随手色”？
- 间距是否成体系（4/8/12/16/24/32…）？组内/组间是否有节奏？
- 卡片是否被当成默认容器？是否有嵌套卡片/幽灵卡片？
- 图标是否统一（线性/填充、粗细、圆角）？是否用 emoji 代替图标？
- 动效是否只有一个主时刻？是否每个 section 同一 fade-up？
- 浏览器默认表面（选择、caret、滚动条、focus ring、下划线）是否与设计协调？
- 暗色模式是否只是反色？语义色/对比度是否仍成立？

## 6. 反 AI 味（快速）

- 紫/淡紫渐变作为主视觉或强调色
- 三张同尺寸“图标+标题+文字”卡片作为页面结构
- 大数字+小标签+辅助统计的 hero 模板
- 每段上方 eyebrow/小标签；无意义 01/02/03
- 渐变文字、玻璃拟态、单边色条、硬偏移阴影作为默认装饰
- emoji/Unicode 字符当图标；系统字体当 display
- 每段 fade-up、每卡 hover 同一效果、无意义循环动画
- 假客户 logo/评价/统计；lorem ipsum；占位图冒充产品
- `transition: all`、布局属性动画、滚动劫持

详见 `anti-slop.md`。

## 7. 设计动作（按目标选一个，不要全做）

| 动作 | 目标 | 主要检查 |
|---|---|---|
| `audit` | 全页体检 | 层级/排版/颜色/布局/状态/a11y/响应式 |
| `critique` | 评审给结论 | P0–P3 + 认知负荷 + Nielsen |
| `polish` | 细节打磨 | 间距/对齐/字号/圆角/阴影/浏览器表面 |
| `harden` | 边界与状态 | 四态/错误/空态/权限/键盘/对比度 |
| `animate` | 动效 | 一个主时刻/reduced-motion/性能 |
| `typeset` | 排版 | type scale/行宽/字重/换行 |
| `colorize` | 色彩 | 中性色/强调色/语义色/暗色/对比度 |
| `layout` | 版式 | 栅格/边距/一屏一任务/卡片滥用 |
| `distill` | 简化 | 删装饰/减层级/合并重复 |
| `bolder` / `quieter` | 强度调节 | 更鲜明/更克制，仍服务 brief |
| `delight` | 记忆点 | 一个真实、可用、不过度的细节 |

每次只做目标动作；不要在设计任务里顺手改无关页面/组件。

## 8. 评审后

- 先修 P0/P1；P2 排期；P3 可选。
- 每轮修改后重新截四个视口；只修复影响项，不扩大范围。
- 修改设计 token 时同步 `DESIGN.md`；不要把一次性覆盖散落在组件里。
- 记录“已检查/未检查/无法验证”，不要用“看起来不错”代替证据。
