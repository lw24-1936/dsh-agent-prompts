# 浏览器验收

> 设计不是“代码写完”就结束；必须在真实浏览器里看渲染结果。优先用项目已有的 Playwright/截图工具；没有就手动打开真实页面，不要只读源码。

## 1. 视口

至少四档：

- **1440×900**：桌面主视口
- **1024×768**：小桌面/横屏平板
- **768×1024**：平板竖屏
- **390×844**：手机

每档检查：

- 无横向滚动/溢出
- 主视觉完整，首屏不出现第二个 section 标题（营销页）
- 文字不截断/不重叠；标题换行合理
- 触控目标 ≥44×44px（移动端）
- 导航/CTA 可点，不被遮挡
- 图片/图表不拉伸变形

## 2. 截图

- 每档至少一张首屏；关键页面/关键状态补全页截图。
- UI 改动要有**改前/改后**对比；没有改前就记录当前基线。
- 截图保存到项目约定目录（如 `.artifacts/`），不要提交临时大图；PR 里附关键图。
- 截图前等待字体/图片/异步数据加载完成；不要截 loading 中间态冒充成品。

## 3. 控制台/网络

- 控制台无 error；warning 逐条判断（第三方/开发模式可解释）。
- 无 404 资源；无 CORS 失败；关键 API 状态码正确。
- 无 hydration mismatch / Vue warning / React key warning。
- 首屏无因图片过大/阻塞脚本导致的明显白屏。

## 4. 交互与键盘

- Tab 顺序合理；focus ring 可见（不要全局 `outline: none`）。
- 键盘可完成主流程；Esc 关闭 modal；Enter/Space 触发按钮。
- modal/drawer 有 focus trap、关闭后焦点回到触发元素。
- hover/focus/active/disabled 状态完整；禁用态不是只降透明度到不可读。
- 表单：label 关联、错误就近、提交中禁用/防重复。

## 5. 四态

每个数据区域/页面至少检查：

- **Loading**：骨架/进度/文案，不是空白闪烁
- **Empty**：说明为什么空 + 下一步动作
- **Error**：说明问题 + 重试/返回；不泄露内部错误
- **边界**：超长文本、空数组、单条/大量数据、权限不足、网络慢/断网

## 6. 对比度与可读性

- 正文/占位符 ≥4.5:1；大字 ≥3:1。
- 彩色背景上的次级文字从该色相/前景推导，不直接灰。
- 暗色模式单独检查；不是简单反色。
- 图片上的文字有可读遮罩/背景。

## 7. 动效与 reduced-motion

- 系统开启“减少动态效果”后，动画/视差/自动播放应停止或降级。
- 动效不阻塞操作；无滚动劫持；无一闪而过的闪烁。
- 只动 transform/opacity 为主；布局属性动画要测量。
- 动画结束态与静态布局一致，不留下偏移。

## 8. 性能（基础）

- 首屏图片有尺寸/懒加载；不加载 5MB 原图当缩略图。
- 字体不造成明显 FOIT/布局抖动；必要时 `font-display`。
- 大列表虚拟化/分页；不一次渲染上千 DOM。
- 第三方脚本延迟/按需；无重复打包大依赖。
- 用 Lighthouse/Performance 面板看 LCP/CLS/长任务；不凭感觉。

## 9. 设计真实感

- 浏览器默认表面（文本选择、caret、滚动条、focus ring、下划线）与设计协调。
- 真实内容/数据；没有 lorem ipsum；占位图/假数据有明确标注。
- 无假客户 logo/评价/统计；没有把参考站资产当自己的。
- 页面看起来属于这个 subject，而不是任意模板。

## 10. 验收记录

```md
## Browser check
- 视口：1440 / 1024 / 768 / 390
- 截图：[路径/链接]
- 控制台：0 error / N warning（说明）
- 键盘：通过 / 问题
- 四态：通过 / 问题
- 对比度：通过 / 问题
- reduced-motion：通过 / 问题
- 未验证：...
```

不要把“截图看起来不错”写成“全部通过”；未检查项明确写未验证。
