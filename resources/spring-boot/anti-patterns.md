# Spring Boot 高频反模式

> 用于 review、重构与排障。每条给出“症状 → 为什么不好 → 修复方向”。

## 结构与边界

1. **按技术层全局平铺包**（controller/service/repository 全放根下）
   - 业务模块边界消失，改一个功能跨十几个目录。
   - 按业务域分包；模块内部实现包内可见；跨模块走 ModuleAPI/事件。

2. **模块之间直接注入对方的 Repository/Entity**
   - 破坏封装，数据库模型变成公共契约。
   - 只暴露 ModuleAPI；需要异步时用领域事件。

3. **shared 变成杂物间**
   - 什么都往里放，最终所有模块依赖 shared。
   - shared 只放真正跨模块的基础类型/错误/事件；业务逻辑留在模块内。

4. **循环依赖用 `@Lazy` 掩盖**
   - 设计边界有问题，延迟注入只是让运行时更晚炸。
   - 先修依赖方向；确实需要异步时用事件。

## Controller / API

5. **Controller 写业务逻辑/事务/SQL**
   - 难测试、难复用、事务边界错误。
   - Controller 只做协议适配；业务在 Service。

6. **直接返回 JPA Entity**
   - 懒加载异常、循环引用、泄露内部字段、API 契约被数据库结构绑死。
   - 返回 Response DTO；Entity 不出持久化层。

7. **请求 DTO 与 Command 混用**
   - HTTP 字段变化直接影响业务层。
   - DTO → Command/Query 的转换放在边界。

8. **所有错误都返回 200 + `{code: 500}`**
   - 客户端/网关/监控无法按状态码处理。
   - 用正确 HTTP 状态；统一 ProblemDetail/错误体。

9. **异常信息直接回传生产**
   - 泄露 SQL/堆栈/内部类名。
   - 统一异常处理；生产隐藏内部细节，日志保留上下文。

10. **分页无上限/排序字段任意拼**
    - 大结果集拖垮服务，SQL 注入/排序注入风险。
    - 限制 page size；排序字段白名单；参数绑定。

## Service / 事务

11. **事务加在 Controller**
    - 事务范围包含序列化/网络，容易长事务。
    - 事务边界放 Service 的写方法。

12. **读方法也开读写事务**
    - 无谓锁/脏读风险。
    - 只读用 `readOnly = true`（按项目事务实现）。

13. **事务里调用远程服务/发 MQ**
    - 远程超时拉长事务，消息与数据不一致。
    - 事务外发消息/事件 + 补偿/outbox（按项目能力）。

14. **先查再改，不做并发控制**
    - 并发下丢更新/重复创建。
    - 乐观锁/唯一约束/条件更新/幂等键。

15. **业务异常用 `RuntimeException("xxx")`**
    - 无法分类映射状态码，调用方只能猜。
    - 领域异常 + 统一映射。

## JPA / 数据库

16. **`open-in-view=true` + 视图层懒加载**
    - 连接持有到渲染结束，性能/事务边界不可控。
    - 关闭 open-in-view；在 Service 内取完所需数据。

17. **每个表一个 Repository，Entity 到处复用**
    - 聚合边界消失，事务/一致性难保证。
    - 只给聚合根建 Repository；跨聚合用 ID/查询。

18. **N+1 查询**
    - 列表页一条主查询 + N 条子查询。
    - fetch join/批量/投影；用测试或 SQL 日志验证。

19. **H2 跑持久化测试**
    - SQL 方言/约束/索引/事务行为与生产不同，测试假绿。
    - Testcontainers 真实数据库。

20. **`ddl-auto=update` 上生产**
    - 不可审计、不可回滚、可能锁表。
    - Flyway/Liquibase 迁移；生产禁用自动建表。

21. **无边界 `findAll()` / 全表 count**
    - 大表拖垮内存/数据库。
    - 分页/条件/投影；需要 count 时评估成本。

## 测试

22. **只有单元测试，没有切片/冒烟**
    - 映射、序列化、安全配置、装配错误都测不到。
    - 补 Web/JSON/持久化切片 + 完整上下文冒烟。

23. **测试依赖顺序/共享状态**
    - 单跑绿、全跑红。
    - 每测独立数据/清理；不共享可变单例。

24. **CI 静默跳过 Docker/集成测试**
    - 假通过；合并后才发现。
    - CI 提供 Docker 或 Testcontainers Cloud；跳过必须显式且不算通过。

25. **为了绿删断言/加 `@Disabled`**
    - 掩盖真实失败。
    - 修根因或明确记录未验证；不静默降低门禁。

## 配置 / 运维

26. **密码/密钥写进 yml/代码**
    - 泄露风险。
    - 环境变量/密钥管理；不提交真实值。

27. **Actuator 暴露全部端点**
    - 泄露配置/环境/线程信息。
    - 只暴露 health/info 等必要端点；生产加认证/网络限制。

28. **日志打印敏感信息/大对象**
    - 合规与性能风险。
    - 脱敏；只打印定位所需字段。

29. **启动时做重业务/远程调用**
    - 启动慢、失败不可恢复。
    - 启动只做装配；重任务异步/后台任务。

30. **没有超时/重试边界**
    - 线程池/连接池被拖死。
    - 连接/读超时、有限重试、熔断/降级按项目能力。

## 快速 review 顺序

1. 包/模块边界 → 2. Controller 职责 → 3. DTO/Entity 隔离 → 4. 事务/并发 → 5. 查询/N+1 → 6. 错误/状态码 → 7. 测试分层/真实数据库 → 8. 配置/日志/Actuator。
