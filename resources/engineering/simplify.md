# 简化：最小正确 diff（Ablation）

> 适用于“改动太大/太绕/加了很多不必要抽象”的清理。目标是**行为不变**的最小 diff，不是最少行数。

## 1. 先定边界

- 只清理当前改动（PR/工作区 diff）引入/修改的代码，以及为移除它必须改的代码。
- 不修无关 bug、不改公共 API、不做顺手重构；发现问题单独报告。
- 用一句话写清改动目标，作为保留/删除的尺子。
- 先跑一遍现有测试/类型检查/lint，记录基线。

## 2. 盘点 diff 的每个“件”

函数、参数、选项、分支、类型、文件、依赖、抽象层、注释、测试。

## 3. 逐件 ablation

问：**删掉它，具体什么会坏？**

| 件 | 删除/内联/合并 | 保留条件 |
|---|---|---|
| 新函数/helper | 内联到调用点 | 2+ 调用，或名字解释了非显然步骤 |
| 包装/抽象层 | 直接调底层 | 隐藏真实复杂度/易变边界 |
| 参数/选项/配置 | 硬编码当前唯一值 | 真实调用方现在就需要不同值 |
| 类型/泛型 | 用推断/已有类型 | 导出，或推断更差/错误 |
| 分支/guard/try-catch | 删掉跑测试 | 守护可达的真实输入/失败 |
| 新文件/模块 | 并入唯一消费者 | 多消费者/独立职责 |
| 依赖 | 用几行/已有依赖替代 | 处理了真实边界情况 |
| 重复逻辑 | 复用已有 util | 仓库没有等价实现（先搜） |
| 注释 | 删除 | 解释 why/约束/踩坑，不是 what |
| 测试 | 删除看谁失去保护 | 覆盖独有行为/回归 |
| 无关改动 | 回退 | 永远不保留 drive-by |

## 4. 保留 vs 删除

删除：

- 为未来需要预埋的选项/钩子/泛型
- 重复语言/框架/已有 util 的能力
- 对不可能情况的防御（类型/调用方已保证）
- 一次性 helper/pass-through/工厂
- 注释掉的代码、叙述性注释、未用 import/export、纯格式化 churn

保留/增加：

- **健壮性**：真实边界（空输入、并发、清理、跨平台路径、错误传播）
- **通用性**：修一般问题，不只修报告里的特例；不要硬编码报告中的名字/路径/值
- **恰当抽象**：第三次重复才抽取；好抽象删除的代码多于新增

目标：读者需要同时持有的概念最少，不是行数最少或层数最多。

## 5. 执行

- 小步删除/内联/合并；每批跑相关测试/类型检查/lint。
- 删除导致失败 → 回退；该件被证明需要。
- 行为不变；不新增功能/不改 API。
- 最后重读 diff：每一行都能被一句话目标解释吗？是否仍健壮/通用？

## 6. 报告

```md
| # | 件 | 动作 | 为什么 |
|---|---|---|---|
| 1 | parseOptions() | 内联 | 单调用，3 行 |
| 2 | retry 选项 | 删除 | 无调用方传值，默认够用 |
| 3 | try/catch | 保留 | 网络错误可达，测试覆盖 |

Diff: +142 -8 → +61 -8。测试/类型/lint 通过。
```

未做的无关发现单独列，不顺手改。

## 7. 自检

- [ ] 只动当前 diff 相关代码。
- [ ] 每件都问过“删掉什么会坏”，有测试/推理依据。
- [ ] 行为不变；没有夹带功能/重构。
- [ ] 删除了预测性/重复/防御不可能/一次性抽象。
- [ ] 保留了真实边界处理与通用性。
- [ ] 最终 diff 能用一句话解释。
