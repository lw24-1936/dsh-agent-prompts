# 证据、验证与审查

## 1. 开工基线

修改前固定：

- 工作目录、分支、当前 commit（或候选身份）、未提交改动。
- 允许写集；已有改动保护；并行工作的互斥写集/共享文件唯一写者。
- 当前工具链、依赖、配置、测试方式、恢复点。

最小实现：先找可复用能力，再决定新增；不凭“文件小/改动少”推定风险低。

## 2. 需求验收

把原始诉求写成：

- 对象、触发、前置条件、输入、预期输出、拒绝条件。
- **改变项** vs **保持项**；未决事项及决策责任。
- 可观察验收：能用明确条件/观察结果判断，不写“体验更好”。

关键语义未定就暂停相交实现；先做不受影响的部分。不要猜业务决定。

## 3. 行为保持

修复/重构/加共享服务入口时：

- 从改点追到实际调用者、参数、分支、返回、副作用。
- 对旧步骤标：原样复用 / 等价保留 / 明确变更 / 有据不适用。
- 覆盖校验、写入、日志、事件、通知、失败补偿中实际存在的部分。
- 没有读到的行为标未知，不宣称“范围外无影响”。

## 4. 风险分级验证

把验收映射到能区分正确/错误的用例：

- 正常、拒绝、边界。
- 实际命中的重复、并发、超时、部分成功、重试。
- 直接变化与必须保持项先验证；再按新失败/验收扩展。
- 分开记录：编译、测试编译、单元/切片、E2E、容器装配、外部联调、部署、现场验收。
- 旧证据只在“候选身份 + 前提”仍有效时复用；否则重跑相交部分。

## 5. 证据状态

| 状态 | 含义 |
|---|---|
| PASS | 当前候选上实际执行，断言/观察满足 |
| FAIL | 当前候选上实际执行，未满足 |
| NOT_RUN | 未执行（环境/权限/预算/依赖） |
| BLOCKED | 前置条件缺失，无法执行 |
| PARTIAL | 只覆盖部分范围/被截断 |
| UNKNOWN | 结果不可确定/来源不可信 |

不要用“命令退出码 0”代替业务断言；不要用“文件存在”代替功能；不要把跳过写成通过。

## 6. 审查：冻结输入 + 可关闭发现

审查前冻结：

- 需求/规则、完整候选身份（commit/diff/hash）、作者、验证结果、读取范围。

发现格式：

```md
- [P0/P1/P2/P3] 位置（文件:行/路由/组件）
  - 触发条件：
  - 预期：
  - 实际：
  - 影响：
  - 修复建议：
  - 关闭标准（可执行）：
```

规则：

- 作者修复，审查者复核“失效项 + 直接依赖”；作者说“已修”不等于关闭。
- 普通自查 ≠ 独立审查；真实分离上下文才能标“独立”。
- 候选/范围变化要重新冻结相交输入；不要用旧绿灯覆盖新候选。
- 不扩大读取无关项目；缺证先限定结论。

### 6.1 有界收敛

同一目标出现具体发现/缺证时，才开整改循环：

- 记录：目标与验收、候选身份、发现 ID、规则/证据版本、已用轮次、时间预算、最早失效阶段。
- 首轮验证/审查计一轮；失败也占轮次；等待也计时。
- 只有“具体最小修复/可区分的新验证/必要补证”才继续；重复读同一结论不算进展。
- 全部必要验收 + 原发现关闭 + 当前候选证据齐全才结束。
- 预算耗尽/无有效下一步 → 停止并交接：已完成、未完成、最早断点、恢复条件。
- 不通过换工具/窗口/候选刷新预算；不重放未知副作用。

## 7. 多轴审查（按风险启用，不凑角色）

| 轴 | 看什么 | 不通过时 |
|---|---|---|
| **代码** | 差异、调用者、副作用、错误处理、边界 | 回作者修，重跑相交验证 |
| **语义** | 需求→实现、实现→需求，是否多/少做 | 未决回需求；违反回实现 |
| **原则** | 范围、目的、旧行为保留、完成声明是否成立 | 缺证补证，不口头通过 |
| **查询/SQL** | 索引、分页、N+1、全表、事务边界 | 回设计/实现；索引建议不是 DDL 批准 |
| **文档** | 目的/适用对象/实际差异/运行命令是否真实 | 文档回作者；运行缺证不改名通过 |

- 简单改动不必五轴全开；高风险/跨模块/数据/权限/支付/安全至少加语义+原则。
- 自查与独立审查分开报告；真实分离上下文才称“独立”。
- 不把“另一个 agent 看过”自动当独立；看它是否拿到同一冻结候选与必要证据。

## 8. 并行与隔离

- 并行任务明确**互斥写集**；共享文件只有一个写者。
- 需要隔离时用 git worktree/临时目录/容器；不要在同一工作区让多个任务互相覆盖。
- 沙箱/容器只约束执行环境，不自动证明业务正确；测试/证据仍要在候选上跑。
- 合并前由集成者审 diff、重跑测试、处理冲突；不假设并行结果天然兼容。

## 9. 能力与预算

- 开始前确认工具/权限/环境是否具备；缺证标 BLOCKED，不编造结果。
- 多轮整改有轮次/时间预算；换工具/窗口不刷新预算。
- 没有能力执行的检查（生产数据、第三方后台、真实支付）明确写未验证，不用模拟结果冒充。
- 预算耗尽交付：已完成、最早断点、未决、恢复条件；不把“没时间”写成“通过”。

## 10. 高影响结论的反证

根因、数据丢失、修复/回滚等高影响判断：

- 分开事实与推断；列首选 + 真实竞争解释（不机械凑数量）。
- 证据矩阵：支持/反对/中性/强反对；不以票数代因果。
- 主动反例：“如果它错了，会观察到什么？”实际查；不能执行就标 NOT_RUN。
- 敏感性：移除关键证据后结论是否改变？关键证据失效就降级/补证。
- 结论限定在候选/来源/覆盖内；修复建议不等于修改权限。

## 11. 自检

- [ ] 候选身份/写集/基线清楚，已有改动未被覆盖。
- [ ] 需求有可观察验收，改变项/保持项分开。
- [ ] 验证覆盖正常/拒绝/边界/实际风险，状态如实。
- [ ] 审查发现可定位、有触发/影响/关闭标准。
- [ ] 候选变化后相交证据已重跑。
- [ ] 收敛有轮次/预算/停止条件，没有假完成。
