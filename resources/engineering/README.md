# 交付纪律（证据、审查、简化）

> 本目录把“实现完成”拆成可验证的证据链，适用于 Java/Spring、前端和一般工程任务。流程选择见技能 `software-engineering-process`。

| 文件 | 内容 | 何时读 |
|---|---|---|
| `evidence-and-review.md` | 需求验收、行为保持、验证分级、发现关闭、收敛、结论反证 | 开工/验证/评审/排障 |
| `delivery.md` | 交付状态、PR/提交、截图证据、恢复点 | 收尾/提交/发布 |
| `simplify.md` | ablation 简化法，保留最小正确 diff | 重构/简化/清理 |

## 三条底线

1. **区分事实、推断、未验证**：不把“代码看起来对”写成“已验证”。
2. **候选变了，旧结论失效**：代码/测试/配置变化后，相交证据要重跑。
3. **不删断言、不跳测试、不假报完成**：修根因或明确记录未验证。
