# Skill 编写指南（本插件实践）

> 从 8 个公开技能包吸收的写法。目标：**模型在正确时机想起它、加载最少内容、执行后能自证**。

## 1. description 决定加载率

- 写“什么时候用 + 覆盖什么 + 关键约束”，不写“本技能介绍……”。
- 用用户会说的词：`Spring Boot`、`Vue 3`、`落地页`、`Code Review`、`Testcontainers`、`401`、`AI 味`。
- 标准类技能在 description 里内联 P0 反例 token，模型即使没加载正文也有强制力。
- 长度控制在 500 字符内；不要把所有细节塞进 description。
- `whenToUse` 是补充，不是唯一触发；不要假设它一定被展示。

## 2. 渐进披露

- `skills/xxx.md` 只放：触发条件、决策表、核心规则、必读路径、自检。
- 细节拆到 `resources/xxx/`，一篇一个主题；主文件给“何时读哪篇”。
- 不要让模型一次读 20 篇；用索引 + 场景路由。
- 资源路径相对 `resources/`，不要写绝对路径。

## 3. 结构模板

```md
# 技能名

> 加载场景：...
> 版本原则：...

## 一、先读项目/确认边界
## 二、核心决策表
## 三、执行规则
## 四、按需资源（表）
## 五、反模式/常见坑
## 六、自检
## 七、来源/许可
```

## 4. 决策表 > 散文

- 把“什么情况选什么”做成表：场景/信号 → 选择 → 产物/门禁。
- 把“症状 → 原因 → 修复”做成表，方便排障。
- 把“默认套路 → 替代”做成表，方便反模式检查。
- 表格要能执行，不写“视情况而定”。

## 5. 自检必须可观察

- 不写“确保代码质量”；写“测试分层完整、持久化用真实数据库、CI 不静默跳过”。
- 不写“设计好看”；写“四视口无横向滚动、正文对比度 ≥4.5:1、四态可见”。
- 不写“已验证”；写“命令 + 结果 + 环境 / 未验证项”。

## 6. 版本与来源

- 不硬绑框架/工具版本；写“按项目 POM/BOM/package.json”，给条件分支（Boot 2/3/4、Vue 2/3、ESLint 8/9）。
- 记录来源仓库/文档与许可；不复制大段原文/代码。
- 生成/更新时记录来源版本或日期，避免 API 过期。

## 7. AGENTS.md 兜底

技能是按需加载，存在 false negative。高频、强约束的规则同时写进 `resources/AGENTS.snippet.md`，由项目 `AGENTS.md` 常驻：

- 什么时候加载哪个技能
- 不可关闭的 P0
- 提交前扫描/测试命令
- 证据/交付纪律

## 8. 可选工程偏好（来自 Anthony Fu Skills，不强加给项目）

这些是“如果项目没有自己的约定”时的可选默认，不是本插件的硬规则：

- 单文件单一职责；大文件按已有边界拆；类型/常量独立文件。
- 显式 import 优先；项目已有自动导入/路径别名时沿用，不新增隐式魔法。
- 注释解释 why，不复述 what；删除注释掉的代码。
- 测试文件与源码同目录 `foo.test.ts`；用 `describe`/`it`；复杂输出用 snapshot，但行为断言优先。
- 运行时无关代码优先 isomorphic；环境特定代码标注 `// @env node` / `// @env browser`。
- 包管理/构建工具（pnpm/ni/UnoCSS/tsdown 等）按项目，不因参考仓库而改。

## 9. 依赖与调用策略

- 不默认安装新依赖；先检查项目已有依赖/工具。
- 第三方能力分三类：自动可用 / 需要外部依赖 / 仅用户明确要求；未满足时先问。
- 使用库 API 前查对应版本文档/类型；不凭记忆写不存在的函数/参数。

## 10. 门禁与反 gaming

- 门禁要能执行（命令/截图/检查表），不能只写“请检查”。
- 不删断言、不跳测试、不弱化 lint、不伪造截图、不改 kit 文件绕过检查。
- 检查失败先修根因；不能修就明确记录未验证/风险。
- UI 门禁用真实浏览器 + 四视口；只读源码不算。

## 11. 本插件的测试

- `test/plugin.test.mjs`：注册数量/顺序/dispose/config。
- `test/content.test.mjs`：技能文件存在、description 长度、版本中立、资源引用可解析、CHANGELOG/README 一致。
- `test/tarball.test.mjs`：打包后技能/资源/文档齐全，安装可加载。
- 新增资源时同步更新 `content.test.mjs` 的 known 集合与 tarball 清单，避免“文件没进包”。

## 12. 提交前自检

- [ ] description 写了触发场景，≤500 字符。
- [ ] 主文件有场景/决策/规则/资源索引/自检。
- [ ] 资源按主题拆分，路径相对 `resources/`。
- [ ] 无硬绑版本；版本差异条件化。
- [ ] 有来源/许可；没有复制大段原文。
- [ ] 高频规则同步 AGENTS 片段。
- [ ] 测试/打包/文档已更新。
